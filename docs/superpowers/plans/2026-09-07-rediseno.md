# Rediseño de Recetario — Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implementar entero el rediseño de `product-design/` sobre la app existente: parser de ingredientes nuevo, índice sin cola ni cache local, borradores con captura por Share Target, búsqueda por ingrediente y tag, modo cocina, Ajustes, y `src/ui/` reescrito con el sistema visual nuevo.

**Architecture:** Se conserva el stack —TypeScript estricto + Vite, sin framework, render por strings de HTML y delegación de eventos desde `#app`— y se conservan `auth.ts`, `drive.ts` y `sheets.ts` sin tocar. Cambian el parser (`recipe.ts`), la fila del índice (`catalogo.ts`) y el store (que pasa a escribir sincrónicamente y pierde la cola, el cache local y la Changes API). `src/ui/` se reescribe entero contra los trece mockups de `product-design/ux/mockups/`. Aparece `src/borradores.ts`, que es una segunda planilla en Drive, y `src/compartido.ts`, la capa que la app y el agente invocan con la misma función.

**Tech Stack:** TypeScript 7 estricto (`noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `verbatimModuleSyntax`), Vite 8, Vitest 4. Sin dependencias de runtime. Sin webfonts.

**Spec:** `product-design/` entero. Los tres documentos que gobiernan este plan:
- `product-design/plan/delta-implementacion.md` — qué cambia archivo por archivo
- `product-design/product/specs/E01…E05.md` — las 91 capacidades con criterios de aceptación
- `product-design/ux/mockups/*.html` + `ux/mockups/tokens.css` — el markup y los valores exactos

## Global Constraints

Valen para **todas** las tareas. No se repiten en cada una.

- **Idioma:** todo en español rioplatense — código, comentarios, nombres de archivo, UI y mensajes de commit.
- **TypeScript:** `npm run typecheck` (que corre `tsc --noEmit` sobre las dos configs) es una puerta obligatoria. Vite borra los tipos, no los verifica. Ningún `any`. Ningún `.js` nuevo.
- **Sin dependencias nuevas.** `package.json` no suma nada.
- **Nada de `src/` apunta a `product-design/`** — ni un `import`, ni un `@import`, ni una ruta de asset. Los tokens se **copian**.
- **R1 — El manejo de errores es un aviso y un botón de reintentar.** Nada más: sin colas de reintento, sin reintento automático, sin recuperación en segundo plano. Ningún error muestra el mensaje crudo de Google. Ningún aviso se cierra solo. Lo que el usuario escribió sigue en pantalla después del error.
- **R2 — El reintento reescribe todo.** Escribir es idempotente: reintentar un guardado a mitad deja exactamente una fila.
- **R4 — El `.md` gana, y la app no lo verifica.** No hay comparación índice-vs-archivo, no hay autorreparación, no hay escritura correctiva al abrir o al listar.
- **R5 — La identidad es el `fileId`.** El archivo no se renombra al editar el título; cambiar la categoría lo mueve de carpeta y actualiza su fila, no crea una nueva.
- **R6 — La app no descubre cambios de afuera.** Sin polling, sin Changes API, sin refresco al volver del segundo plano.
- **R7 — Android y navegador de escritorio.** iOS no se soporta.
- **C05.4.2 — No hay copia local del índice.** Ni IndexedDB, ni `localStorage`, ni nada del navegador.
- **El éxito no se comunica.** Ningún cartel confirma que algo salió bien (decisión 8 del delta).
- **Un solo tema oscuro**, sin `prefers-color-scheme`.
- **Tipografía del sistema.** Sin webfonts: `--tipo` es la pila de `system-ui`.
- **Toque mínimo 48 px**, salvo el modo cocina, que es la única excepción hacia arriba (64 px).
- **Commits frecuentes**, uno por tarea como mínimo, con el estilo del repo: una línea de asunto que diga qué cambió el producto, no qué archivo se tocó.

### Decisiones tomadas al planificar

Dos cosas que el delta no resolvía explícitamente y que quedan fijadas acá:

1. **`sync()` y `diffCambios()` se eliminan.** R6 y el decision-log (2026-09-06, «Sin detección, sin polling, sin registro de vistas») descartan la Changes API. Se van `store.sync()`, `catalogo.diffCambios()`, `drive.cambios`, `drive.tokenInicialDeCambios`, la clave `changesPageToken` de la hoja `meta`, y `tests/catalogo-diff.test.ts` y `tests/store-sync.test.ts` enteros.
2. **El chequeo de conflicto por `modifiedTime` sale de `guardar()`.** `[decisión del usuario, 2026-09-07]` C04.5.1 describe guardar sin comprobación y R4 prohíbe comparar el índice contra Drive. Guardar pisa lo que haya. El riesgo aceptado: si un agente reescribió el `.md` con la receta abierta, ese cambio se pierde.

### Supuesto declarado

**Las columnas del índice se agregan, no se reemplazan.** C05.4b.1 nombra `fileId`, título, categoría, tags, completitud, fuente, foto e ingredientes, pero la tarjeta miniatura de C02.5b.1 muestra el tiempo y la lista de categoría necesita `carpeta_id`. Se leen esas ocho como el mínimo garantizado, no como una lista excluyente: se conservan las doce columnas actuales y se suman `foto` y `completa`.

- [ ] **Step 4: Reescribir el parser en `src/recipe.ts`**

Borrar la constante `UNIDADES` entera y reemplazar `parseIngrediente`:

```typescript
/**
 * Nombre + separador + cantidad (C05.1.3). Manda el primer separador que
 * aparece, salvo la coma, que solo separa si le sigue un dígito: sin esa
 * regla `Sal, pimienta` daría el ingrediente "Sal" con cantidad "pimienta".
 */
const SEPARADORES = ['-', '—', ';', ',', '|'] as const;

export function parseIngrediente(linea: unknown): Ingrediente | null {
  if (typeof linea !== 'string') return null;
  const crudo = linea;
  const limpia = crudo.replace(/^\s*[-*]\s+/, '').trim();
  if (!limpia || limpia.startsWith('#')) return null;

  let corte = -1;
  for (let i = 0; i < limpia.length; i++) {
    const c = limpia[i];
    if (!c || !(SEPARADORES as readonly string[]).includes(c)) continue;
    // La coma pide un dígito después, salteando espacios.
    if (c === ',' && !/^\s*\d/.test(limpia.slice(i + 1))) continue;
    corte = i;
    break;
  }

  if (corte === -1) return { nombre: limpia, cantidad: null, crudo };
  const nombre = limpia.slice(0, corte).trim();
  const cantidad = limpia.slice(corte + 1).trim();
  return { nombre, cantidad: cantidad || null, crudo };
}

/** Los nombres, tal como están escritos: sin normalizar (C05.4b.1). */
export function ingredientesIndexables(receta?: Partial<Receta> | null): string[] {
  if (!receta) return [];
  const vistos = new Set<string>();
  for (const linea of String(receta.ingredientes ?? '').split('\n')) {
    const ing = parseIngrediente(linea);
    if (!ing?.nombre) continue;
    vistos.add(ing.nombre);
  }
  return [...vistos];
}
```

Ojo con el `-` inicial: `limpia` ya viene sin el bullet, así que `- — 4` llega como `— 4` y corta en el `—`, dando nombre vacío. Para `- Milanesas de nalga — 4` el primer separador es el `—`, no el bullet, porque el bullet se sacó antes.

```typescript
/** Parte un texto de sección por sus `###`. El texto antes del primero es el tramo sin nombre. */
function porSubsecciones(texto: string): { nombre: string; cuerpo: string }[] {
  const partes: { nombre: string; cuerpo: string }[] = [];
  let nombre = '';
  let buffer: string[] = [];
  const volcar = () => {
    const cuerpo = buffer.join('\n').trim();
    if (cuerpo || nombre) partes.push({ nombre, cuerpo });
    buffer = [];
  };
  for (const linea of String(texto ?? '').split('\n')) {
    const m = linea.match(/^###\s+(.+?)\s*$/);
    if (m?.[1]) { volcar(); nombre = m[1].trim(); continue; }
    buffer.push(linea);
  }
  volcar();
  return partes;
}

export function gruposDe(ingredientes: string): GrupoIngredientes[] {
  return porSubsecciones(ingredientes).map(({ nombre, cuerpo }) => ({
    nombre,
    items: cuerpo.split('\n').map(parseIngrediente).filter((i): i is Ingrediente => i !== null)
  }));
}

/** Un paso es una línea que empieza con `1.` o con un bullet. El número no se conserva: se recuenta al dibujar. */
export function tramosDe(preparacion: string): TramoPreparacion[] {
  return porSubsecciones(preparacion).map(({ nombre, cuerpo }) => ({
    nombre,
    pasos: cuerpo.split('\n')
      .map(l => l.replace(/^\s*(?:\d+[.)]|[-*])\s+/, '').trim())
      .filter(Boolean)
  }));
}

export function variacionesDe(variaciones: string): { lista: string[]; secciones: Variacion[] } {
  const partes = porSubsecciones(variaciones);
  const conNombre = partes.filter(p => p.nombre);
  if (conNombre.length === 0) {
    const lista = String(variaciones ?? '').split('\n')
      .map(l => l.replace(/^\s*[-*]\s+/, '').trim())
      .filter(Boolean);
    return { lista, secciones: [] };
  }
  return {
    lista: [],
    secciones: conNombre.map(({ nombre, cuerpo }) => {
      // Una línea en itálica al empezar es la fuente de la variación (IA §1.8).
      const m = cuerpo.match(/^\*(?:fuente:\s*)?(.+?)\*\s*(?:\n|$)/i);
      return {
        nombre,
        fuente: m?.[1]?.trim() ?? null,
        cuerpo: (m ? cuerpo.slice(m[0].length) : cuerpo).trim()
      };
    })
  };
}
```

/**
 * Estado derivado, calculado al leer y nunca persistido en el `.md`
 * (C05.3.1). `completa: true` es la salida manual del usuario y gana.
 */
export function estaCompleta(receta: Receta): boolean {
  if (receta.completa) return true;
  if (!receta.titulo) return false;
  const hayIngrediente = gruposDe(receta.ingredientes).some(g => g.items.length > 0);
  const hayPaso = tramosDe(receta.preparacion).some(t => t.pasos.length > 0);
  return hayIngrediente && hayPaso;
}
